= AsciiChem

AsciiChem is an ASCII syntax for representing chemistry: atoms, molecules,
bonds, reactions, electron configurations, and embedded mathematics. It
parses to a semantic model and renders to MathML, HTML, LaTeX, and SVG.

== Why

AsciiMath is insufficient for chemistry:

* Prefix superscripts/subscripts have no atom to bind to — AsciiMath
  forces a phantom `{}` carrier (e.g. `{}^14C`), which is semantically
  wrong: the isotope belongs to the atom, not to an empty element.
* No native syntax for stoichiometric coefficients, reaction arrows,
  conditions, or spectator ions.
* No representation for electron configuration, term symbols, or bonds.
* No structural diagrams.

AsciiChem closes these gaps.

== Installation

Add to your Gemfile:

[source,ruby]
----
gem "asciichem"
----

Or install directly:

[source,sh]
----
$ gem install asciichem
----

== Usage

[source,ruby]
----
require "asciichem"

formula = AsciiChem.parse("H_2O")
formula.to_mathml  # => "<math>...</math>"
formula.to_text    # => "H_2O"  (round trip)
----

The parsed model is the canonical form: MathML, HTML, LaTeX, text,
linear and 2D structural SVG, and CML are views over the same tree.

=== Structures: SMILES and molfile in, AsciiChem out

[source,ruby]
----
formula = AsciiChem.parse_smiles("CC(=O)Oc1ccccc1C(=O)O")
formula.to_structural_svg   # 2D depiction, deterministic layout
formula.to_smiles           # canonical aromatic SMILES
formula.to_text             # AsciiChem text

formula = AsciiChem.parse_molfile(molfile_text)   # V2000 in and out
----

=== Lint

[source,ruby]
----
AsciiChem::Linter.run(formula)   # chemistry diagnostics: balance,
                                 # valence, charge, isotopes, rings,
                                 # identifier consistency, ...
AsciiChem::Linter.errors?(formula) # => true/false
----

=== Local identity: InChI, AuxInfo, InChIKey

[source,ruby]
----
require "asciichem/inchi"

# the native chemomer engine (byte-exact vs the IUPAC oracle;
# CHEMOMER_LIB points at the built cdylib) or the IUPAC binary:
AsciiChem::Inchi.engine = AsciiChem::Inchi::NativeEngine.new

identity = AsciiChem::Inchi.identity_for(molecule)
identity.inchi     # "InChI=1S/C9H8O4/..."
identity.inchikey  # "BSYNRYMUTXBXSQ-UHFFFAOYSA-N"
----

=== Resolution: identifiers to substance records

[source,ruby]
----
require "asciichem/resolver"

substance = AsciiChem::Resolver.resolve(value: "50-78-2", convention: "cas")
substance.preferred_name        # => "Aspirin"
substance.structure.to_smiles   # from the source record
substance.identifiers.first.provenance.source   # "common_chemistry"

# all shipped sources (PubChem, OPSIN, CAS Common Chemistry) resolve
# by default; attribution rides every record. Limit the set when a
# use must stay NC-free:
AsciiChem::Resolver.resolve(value: "50-78-2", convention: "cas",
                            sources: [:pubchem, :opsin])
----

CAS key-gated the Common Chemistry API: live lookups there need a
personal token (request one at cas.org/services/commonchemistry-api,
valid 12 months). Export it as `COMMON_CHEMISTRY_API_KEY` or store
it at `~/.config/cas-common-chemistry-api.key` — the adapter sends
it as the `X-API-KEY` header. Without a key, that source answers 401
and is skipped — PubChem and OPSIN keep resolving.

=== Citations: dataset bibitems with provenance

[source,ruby]
----
require "asciichem/citation"

molecule = AsciiChem.parse("CC(=O)OC1=CC=CC=C1C(=O)O @cas(\"50-78-2\") @cite(\"pubchem\")").nodes.first
AsciiChem::Citation.for_molecule(molecule)
# => [["pubchem", #<Relaton bibitem>]] - one dataset-type bibitem per
# (substance, source), anchored by InChIKey, with a provenance note
# (retrieved from, version, attribution).
----

== Command line

[source,sh]
----
asciichem convert -i "H_2O" -t mathml        # also: --from smiles|molfile
asciichem identity -i aspirin.smiles --from smiles
asciichem resolve --cas 50-78-2 --source common_chemistry
asciichem validate -i 'H_2O @cas("50-78-2")'
asciichem cite --cas 50-78-2 -t model-json
asciichem lint -i "2H_2 + O_2 -> 2H_2O"
asciichem roundtrip -i "C_6H_12O_6"
asciichem parse-cml -i formula.xml
----

== Conformance

The reference implementation of https://www.asciichem.org[the AsciiChem
contract]. Every claim is gated by the shared corpus
(https://github.com/asciichem/asciichem-tests[asciichem-tests]) in CI —
a level without the green corpus run behind it does not ship.

[cols="1,1,4"]
|===
|Level |Claim |Basis

|L0 notation |yes |parse/reject contract; every `roundTrip` fixture returns its input
|L1 semantics |yes |wire form validates against the v1 schemas and round-trips; the perception pass (implicit hydrogens, aromatic rings) is corpus-gated
|L2 render |yes |MathML byte-goldens, canonical text, and the wire form for every construct
|L3 stereo |yes |tetrahedral chirality, directional bonds, wedge/hash; parity-correct canonical SMILES including ring closures
|L4 identity |yes |opt-in InChI engine (binary or native) with stereo layers, OPSIN adapter, identifier cross-check, resolver (PubChem, OPSIN, and Common Chemistry on by default — CC BY-NC attribution carried everywhere; limit sources with `Resolver.resolve(sources:)`), citation bibitems
|===

TypeScript and Python claim the same levels they pass; see their
READMEs and the https://www.asciichem.org/guides/conformance-levels/[levels
document].
